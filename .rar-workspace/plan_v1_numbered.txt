   1|# 新增 `okf-frontmatter` skill，并与 Markdown 转换显式联动
   2|
   3|## Summary
   4|
   5|- 新增独立 `/file-processing:okf-frontmatter` skill。原因是 OKF frontmatter 包含 `type / description / tags` 等语义判断，不应硬编码进确定性的格式转换管线。
   6|- `markdown-conversion` 增加显式 OKF 模式；默认行为保持兼容，只有指定 `--okf` 或 `--workspace` 才联动新 skill。
   7|- 通用模式满足 OKF 0.1；Cortex 模式额外读取 authoring profile 和活动 policy。所有写入均采用“Agent 提议 → 展示差异 → Plan → Apply”。
   8|- 不修改 Cortex；仅通过其只读 CLI 接口获取 workspace、target 和 policy 状态。
   9|
  10|## 公开接口
  11|
  12|- 新命令：
  13|  - `/file-processing:okf-frontmatter <file-or-directory>`
  14|  - `--workspace <cortex-root>`：启用 Cortex 2.1 policy 模式。
  15|  - `--no-recursive`：目录输入时不递归。
  16|  - `--metadata-json <path>`：提供人工确认的字段。
  17|  - `--replace-fields <csv>`：显式允许覆盖已有非空字段；默认仅补缺。
  18|  - `--plan-only`、`--apply-plan <plan>`：分离审核与应用。
  19|  - `--accept-partial`：批量任务中明确允许只应用完整项目。
  20|- `markdown-conversion` 新增 skill 层参数：
  21|  - `--okf`：生成通用 OKF-ready Markdown。
  22|  - `--workspace <path>`：隐含 `--okf`，并满足 Cortex authoring 与活动 policy。
  23|  - `--no-frontmatter` 与上述参数互斥。
  24|- 新脚本提供 `prepare / publish / apply / validate` 子命令；计划绑定源文件 SHA-256、渲染结果 SHA-256、目标路径及 Cortex policy digest。
  25|
  26|## Implementation Changes
  27|
  28|- `okf-frontmatter` 使用 `ruamel.yaml` round-trip 解析，保留已有字段、未知扩展、顺序、引号、注释和正文；拒绝重复键、非 mapping 或损坏的 YAML。
  29|- 字段优先级为：显式用户输入 → 已有非空值 → 确定性推导 → Agent 建议。默认生成 `type/title/description/timestamp`；保留转换产生的 `source/converted_at/converted_by`。
  30|  - 标题优先取首个 H1，再取文件名。
  31|  - 时间优先取原始来源文件 mtime，再取 Markdown mtime或转换时间。
  32|  - URL 可写入 `resource`；本地路径只保留在 `source`。
  33|  - 不自行生成 `source_ids`，由 Cortex publish 流程管理。
  34|- Cortex 模式先验证 method contract 为 2.1、18 个公开 schema及目标操作集合，再读取 `manage config show` 和 quick validation：
  35|  - 有效 policy：要求 authoring 四字段与 `required_frontmatter_fields` 的并集，并校验声明文件摘要。
  36|  - policy 缺失：可生成通用 authoring frontmatter，但明确标记为“policy 未验证”。
  37|  - policy 无效、CLI 不兼容或自定义必填字段无可靠依据：阻止 Apply。
  38|- `index.md`、`log.md` 不作为普通 concept 注入 frontmatter；UTF-8 BOM、符号链接及活动 Cortex bundle 内的直接修改均被阻止或单独报告。受管 bundle 只能经 Cortex 计划执行。
  39|- `markdown-conversion --okf` 先把无 frontmatter 的转换正文写入运行暂存区，再把来源字段交给新 skill。只有 frontmatter 计划获批并通过校验后才创建最终输出；拒绝审核或失败时不留下伪称 OKF-ready 的目标文件。
  40|- 默认 legacy 转换路径及其现有三字段 frontmatter保持不变。插件版本升至 `3.6.0`，`markdown-conversion` 升至 `4.1.0`，新 skill 为 `1.0.0`；同步更新已获授权的 `AGENTS.md`、README 和插件清单。
  41|

  54|## Assumptions
  55|
  56|- “cotex”按已确认解释为 Cortex CLI，而非 OpenAI Codex。
  57|- 首版处理普通 concept Markdown；不负责生成 bundle `index.md`、日志、Cortex 索引或执行 publish。
