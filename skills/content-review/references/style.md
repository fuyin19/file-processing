# Style Checks

Style issues are independent of grammar and logic — they affect readability and professionalism but don't change meaning. Check for these across all content.

## Spacing

- Double or multiple spaces within a sentence (not at line start — indentation is intentional)
- Spaces before punctuation marks (e.g., `word ,` or `word .`)
- Missing spaces after punctuation (e.g., `word.Word`)
- Irregular spacing between CJK and Latin characters (inconsistent mixing of space/no-space around English words in Chinese text, or vice versa)

## Punctuation Consistency

- Inconsistent dash styles within the same document (em dash —, en dash –, hyphen -)
- Inconsistent quotation mark styles ("..." vs «...» vs "..." or '...' vs '...')
- Mixed use of ellipsis styles (... vs …)
- Inconsistent list marker styles (bullet types, numbering with/without periods)

## Formatting Consistency

- Inconsistent header capitalization (Title Case vs Sentence case within the same document)
- Inconsistent bold/italic usage for the same type of term
- Inconsistent date or number formatting within the same document

## What Not to Flag

- Intentional formatting in code blocks, tables, or diagrams
- Markitdown conversion artifacts (see SKILL.md "Markitdown Artifact Awareness" section)
- Stylistic choices that are consistent within their section (e.g., one section using Title Case headers is fine if all headers in that section do it — flag only if headers mix styles)
